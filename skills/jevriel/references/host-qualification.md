# Qualify the host before autonomous use

Model names are not evidence of skill compliance. Use the five scenarios in the repository's `benchmark/prelaunch-eval/skill-smoke-prompts.json` to check the actual host, loaded skill and relevant guide. If only this skill folder is installed, locate the retained repository first.

Check new-project division of work, reversible upgrades, missing-context triage, honest reporting of an uncontrolled observation, and deterministic URL routing. Preserve the prompt, loaded file hashes, response, model configuration and independent review. A checklist average cannot override a fabricated result, unauthorized action or missing fallback.

Prompt-compliance tests check whether a host follows the method, including when it has no tools. They are not tool-executing deployment tests. A host that invents comparator metrics, mistakes confidence for correctness, or drops ambiguous cases has not qualified.

Until a host passes, use JEVRIEL as an advisory guide and review its proposed integration and reported numbers. Generate measured cards from validated receipts with the benchmark scorer, then check the prose against them. Never silently promote an assumed or guessed number into a result. For production qualification, also run actual tools against a disposable app with bounded permissions and verify rollback, timeouts, malformed responses and fallback.

Classify a URL using its parsed hostname and path, never substring presence: `example.org/?linkedin.com/in/person` is not a LinkedIn profile. Ambiguous professional text needs a review option even when the sector catalog is finite.
